# AI Review Auto-Reply

Automatically replies to Google reviews across ACE Training and MultiSkills Training's 8 campuses:
fetch new reviews → draft an on-brand AI reply → auto-post the safe ones, hold risky ones for human
approval → post and log the result.

Built from `ACE & MST_Review_AutoReply_Proposal.pdf` (what the client bought) and `step-by-step.pdf`
(how it should be built).

## Structure

```
review-autoreply/
├── .env              ← ONE config file for everything (gitignored)
├── .env.example      ← the template, committed
├── package.json      ← scripts you run; lists the two workspaces
├── node_modules/     ← ONE shared install for both apps
├── backend/          ← NestJS API + Prisma + PostgreSQL
│   ├── package.json      its dependency list only
│   ├── prisma/           schema, migrations, seed
│   └── src/
│       ├── config/       env validation
│       ├── common/       Prisma service
│       ├── auth/         login, JWT
│       ├── users/
│       ├── brands/       AI tone/rules per brand
│       ├── locations/    campuses
│       ├── reviews/      storage, dedupe, pipeline orchestration
│       ├── ai/           reply generation (swappable provider)
│       ├── safety/       auto-post vs human-approval routing
│       ├── replies/      edit / approve / reject
│       ├── notifications/ Slack + email alerts
│       └── reports/      dashboard stats
├── frontend/         ← Next.js dashboard
│   ├── package.json      its dependency list only
│   └── src/
│       ├── app/          pages
│       ├── components/   UI
│       ├── lib/          API client, auth state
│       └── types/        API contract types
└── docs/             ← architecture, database, credentials, setup
```

This is an **npm workspace**: one `node_modules` and one `package-lock.json` at the root serve both
apps, so `npm install` is run once, from the root. The `package.json` inside `backend/` and
`frontend/` only lists that app's dependencies — you rarely need to open them.

The two `tsconfig.json` files genuinely cannot be merged: NestJS compiles to CommonJS with
decorators, Next.js to ESM with JSX, and those settings contradict each other.

Folders you'll see in your editor but never in git — all ignored on purpose:

- **`node_modules/`** — installed dependencies. Never edit or commit; `npm install` recreates it.
- **`dist/`, `.next/`** — compiled build output. Regenerated by `npm run build`.

## Quick start

Everything runs from the project root — one install, one command.

```bash
# 1. Configure — copy the template and fill in your values
copy .env.example .env
#    (see docs/CREDENTIALS.md for what each value is and where to get it)

# 2. Install both apps at once
npm install

# 3. Set up the database
npm run db:migrate      # create the tables
npm run db:seed         # brands + admin user

# 4. Start both apps together
npm run dev             # API on :4000, dashboard on :3100
```

Then open <http://localhost:3100> and sign in.

Default seeded login is `admin@example.com` / `change-me-now` — unless you set `ADMIN_SEED_EMAIL`
and `ADMIN_SEED_PASSWORD` in `.env` *before* seeding, which you should for anything real.

Full setup instructions including PostgreSQL and Redis on Windows: **[docs/SETUP.md](docs/SETUP.md)**

**Working end to end right now:** sign in; browse the review inbox with live stats; the AI drafts a
reply per review in that brand's configured tone; the safety router auto-approves clean reviews and
holds risky ones — low-rated *or* containing sensitive content, including a 5-star review that hides
a complaint; staff edit / approve / reject from Reviews or Alerts; the monthly report charts real data.

**What is still simulated:** reviews come from a seed script rather than from Google. Connecting a
real Google Business Profile (phase 10) swaps the seed for live fetching and posts approved replies
back — every other stage of the pipeline is already built and does not change.

Try it:

```bash
npm run db:seed-reviews   # 8 sample reviews, incl. a 5-star one containing a complaint
npm test                  # safety router test suite

# then add OPENAI_API_KEY to .env and run the pipeline from the dashboard,
# or: POST /reviews/process with a bearer token
```
